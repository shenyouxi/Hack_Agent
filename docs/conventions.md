# Naming and Interface Conventions
Agree on these before adding code. If this file conflicts with the build prompt or patches, this file wins.

## Language rule
All files must be written in English: code, comments, docstrings, JSON data, markdown docs, log messages, error messages, commit messages, and UI text. Ingredient names are English lowercase (e.g. "heavy cream"). All external search queries are English. Chat between teammates may use any language.

## Naming rules
- Files/modules, functions, variables: snake_case
- Classes and interfaces: PascalCase
- Constants: UPPER_SNAKE_CASE

## Name table
- models -> pantry/models.py
- config -> pantry/config.py
- rules (constants ALLERGEN_MAP, STAPLES, ALIASES; data loaded from seed_data/*.json) -> pantry/rules.py
- Store / JsonStore / MongoStore -> pantry/store/base.py, json_store.py, mongo_store.py
- LinkupClient / FakeLinkupClient -> pantry/tools/linkup.py
- TavilyClient / FakeTavilyClient -> pantry/tools/tavily.py
- LLM (abstract) / OpenNextLLM / FakeLLM -> pantry/llm.py
- Initial data: seed_data/ at repo root (handwritten); demo script data in seed_data/demo_script.json
- Scripts: scripts/seed.py, preflight.py, reset_demo.py, prewarm.py
- Run (maps to the runs collection, includes steps); Trace (maps to decision_traces, used for retrieval) -> pantry/models.py
- API notes: docs/api_notes.md (not doc/)

Note: the official Linkup and Tavily SDKs also define classes with the same names. Always rename them on import:
from linkup import LinkupClient as SdkLinkupClient
from tavily import TavilyClient as SdkTavilyClient

## Interface signatures
Real and Fake implementations must match: same signature, same return type. Fakes are deterministic.

class Source(TypedDict): title: str; url: str; content: str
class LinkupResult(TypedDict): answer: str; sources: list[Source]
class LinkupClient:  def search(self, query: str, depth: str = "standard") -> LinkupResult
class TavilyClient:  def extract(self, url: str) -> dict   # {"url": str, "content": str}
class LLM:  def chat_json(self, system, user, schema) -> dict;  def embed(self, texts) -> list[list[float]]

- Linkup returns an answer plus sources, because the Resolver needs the sourced answer text and its citations.
- One field naming across the project: title, url, content. SDK "name" maps to title and "snippet" maps to content, converted once inside the wrapper class. Never mix text, snippet, or content elsewhere.
- Every MongoDB connection must pass tlsCAFile=certifi.where(). Load .env with load_dotenv(".env"), never the no-argument form.

## Data conventions
- Ingredient (pantry_items) fields: item_name, aliases, category, quantity, reserved, unit (pcs/g/ml), expiry_offset_days (used in seed JSON; seed.py converts it to expiry_date), safety_stock, allergen_tags. priority_score and last_updated are computed by code. There is no label_zh field.
- Seed traces (seed_data/seed_traces.json) use structured fields: trigger, expiring, have, constraints, allergens, plan, final_outcome. snapshot_text and embedding are generated by seed.py with the same function used at runtime.
- Trace fields: trace_id, run_id, day_index, trigger, plan, retrieved_traces, resolver_actions, steps, risk_status (none | allergen | no_citation | search_unavailable | constraint_violation), final_outcome, is_seed, created_at. Use the class name Trace, not TraceRecord.
- Feedback: Store.save_feedback(trace_id, outcome, op_id, source) -> Feedback. op_id is idempotent. Auto-accept also writes feedback (source="auto", op_id="auto:" + trace_id). The UI triggers feedback through a FEEDBACK command and shows the result only after the command status is done. Rejecting an already-applied plan is equivalent to undoing its reservation.
